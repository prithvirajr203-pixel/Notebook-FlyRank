Predicting Search Visibility Loss: A February-to-March Went-Dark Model

Which measurable search and page-level signals foreshadow a page losing all clicks the following month?
ML Track · Week 8 Capstone · Built on 79M+ rows of anonymized production search data

Abstract

This paper asks which measurable February page and search characteristics are most associated with a page going "dark" — receiving zero clicks — in March. Using aggregated Google Search Console signals and content metadata for 29,353 eligible pages, we built a binary classifier comparing a majority-class baseline against Logistic Regression and HistGradientBoosting models, with strict exclusion of any March-derived features to prevent target leakage. The majority-class baseline achieved 96.05% accuracy but zero recall, illustrating that accuracy is a misleading metric on this 3.95%-positive-rate problem; HistGradientBoosting achieved the strongest ranking ability (ROC-AUC 0.87, PR-AUC 0.22), while Logistic Regression achieved the highest recall (87.93%) at the cost of precision. February clicks and impressions emerged as the two strongest predictive signals by a wide margin, followed by content length. We frame all results as directional, predictive associations rather than causal claims, and provide a ranked, threshold-aware action playbook for prioritizing pages for manual SEO review.

1. Introduction & Problem Statement

Search-visible pages sometimes lose all organic traffic from one month to the next — a page that was earning clicks in February can go completely dark in March with no obvious warning. For a content or SEO team managing thousands of pages, catching this early is the difference between a quick fix and a quarter of lost traffic.

This project asks a narrow, testable question: using only information available in February, can we identify which pages are at elevated risk of going dark in March, and which February signals carry the most predictive weight?

The decision this supports is directional, not prescriptive: a ranked, review-worthy list of pages for an SEO team to investigate before visibility is lost — not an automated verdict on any individual page.

2. Data

This analysis draws on the FlyRank ML Internship dataset (FlyRank/internship-warehouse), an anonymized production search-performance warehouse of roughly 79 million rows, accessed via the gated Hugging Face release.

Tables used

  • fact_content_daily_performance — daily Google Search Console and GA4 metrics per page, partitioned by month.
  • dim_content — content and keyword metadata (word count, backlinks, search volume, competition, publish status).

Date windows

  • Feature window: February 2026 (month=2026-02)
  • Label window: March 2026 (month=2026-03)

Eligibility & exclusions

The February universe was built with the following filters, applied to keep the analysis meaningful and public-safe:

  • At least 100 February impressions and 3 February clicks (excludes pages too sparse to have a measurable baseline).
  • Page must be published and not deleted.
  • Content must have been created on or before February 28, 2026 (excludes pages that couldn't have a full February of history).
  • Page must have at least one measured day of Search Console data in March (excludes pages with no March measurement at all — a missing March record is not treated as zero performance).

No client names, URLs, keywords, or other identifying strings are used or displayed anywhere in this paper or the accompanying notebook — only hashed IDs and aggregated numeric signals, consistent with the dataset's anonymization and the internship's data-use terms.

3. Methodology

3.1 Label definition

The target variable, went_dark, is binary: 1 if a page recorded zero Search Console clicks across all measured March days, 0 otherwise. Of the 29,353 eligible pages, 1,159 (3.95%) went dark — a highly imbalanced target.

3.2 Features

Thirteen February-only features were used as model input:

  • Search performance: impressions, clicks, CTR, average position (all February)
  • Content characteristics: word count, character count, URL length
  • Keyword characteristics: keyword character count, keyword token count
  • External signals: search volume, competition, backlinks, category count

3.3 Leakage checks

All March-derived fields (impressions_mar, clicks_mar, measured_days_mar) were deliberately excluded from the feature set — they exist only to construct the label, never as predictors. Content creation dates were also checked against the February window boundary to ensure no page was included that hadn't had a full month of exposure yet.

3.4 Missing-value handling

Missing values appeared in word_count, char_count, search_volume, competition, and backlinks. Rather than dropping rows (which risks biasing the sample toward better-documented pages), we used median imputation inside a pipeline for Logistic Regression, and relied on HistGradientBoosting's native missing-value handling as a second model.

3.5 Validation design

An 80/20 stratified train/test split (random_state=42) preserved the 3.95% positive rate in both sets: 23,482 training pages (927 positive) and 5,871 test pages (232 positive).

3.6 Baseline

A majority-class Dummy Classifier, predicting went_dark = 0 for every page, served as the baseline — the standard "how good is doing nothing" comparison for an imbalanced problem.

4.4 Interpretation

February click and impression volume dominate as predictive signals — far more than any content or keyword attribute. This suggests that a page's own recent search-performance trajectory is the strongest early-warning signal available, ahead of static content or keyword characteristics. Content length (char_count) was a distant third, suggesting thin content carries some elevated risk but is a much weaker signal on its own.

These are predictive associations, not causal claims. High importance for clicks_feb means it helps the model distinguish pages that later went dark from pages that didn't — it does not mean low clicks cause a page to go dark.

5. Limitations & Honest Framing

  • Limited time window. The model observes one month (February) predicting one following month (March). Results may not generalize across seasons or longer periods.
  • Severe class imbalance. Only 3.95% of pages went dark. Even with class weighting and threshold tuning, false positives remain substantial at any recall level worth acting on.
  • Association, not causation. Feature importance identifies useful predictors, not causal drivers of visibility loss.
  • Threshold sensitivity. HistGradientBoosting's recall swings from 0.43% to 80.17% depending solely on the chosen decision threshold — the "right" threshold depends entirely on intended use, not on the model itself.
  • Missing features. Technical SEO issues, indexing status, algorithm updates, and site-level changes are not represented in this dataset and could be substantial confounders.
  • Missing data in inputs. Backlinks, word count, and char count had missing values; imputation may have introduced noise the model does not account for.
  • Single train/test split. No cross-validation or temporal rolling validation was performed — results should be treated as a single-run estimate, not a stable benchmark.
  • Not yet operationally validated. This model has never been used in a live SEO monitoring workflow; its practical usefulness for review prioritization is untested.

6. Ranked Recommendations

  1. Monitor February click/impression drops as the primary early-warning signal

    These were by far the two strongest predictors. Flag pages with a sharp month-over-month decline in either metric for review before the following month closes.

  2. Treat thin content (low char_count) as a secondary risk flag

    Shorter pages showed elevated went-dark association. Prioritize auditing short pages that are also showing declining engagement.

  3. Use CTR and average position as supporting, not standalone, signals

    Useful for ranking which flagged pages to review first, but too weak individually to trigger action alone.

  4. Choose the decision threshold based on review capacity

    Use ~0.05–0.15 for broad monitoring with more false positives; use a higher threshold (~0.35+) for a short, high-precision list when review time is limited.

  5. De-prioritize backlinks, search volume, competition, and category count as standalone triggers

    These contributed only marginal predictive value in this window and dataset.

  6. Re-validate on a longer time window before any operational rollout

    These recommendations are directional, based on a single two-month observation period, and should be confirmed against additional months before being trusted in a live workflow.
