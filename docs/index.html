Predicting Search Discoverability Loss with Machine Learning

Using historical search-performance and content signals to identify pages that may require human investigation before their discoverability declines.

Prithiviraj R.
Machine Learning Track · FlyRank ML Internship

Abstract Introduction Data Methodology Results Limitations Recommendations Reproducibility Acknowledgments

1. Title + Abstract

Question: Can historical search-performance and content signals help identify pages that are at risk of losing search discoverability?

Data: This study uses the FlyRank ML Internship dataset, using a February 2026 feature window and a March 2026 outcome window, with 29,353 pages in the final modeling dataset.

Method: A dummy classifier was used as a baseline and compared with Logistic Regression and HistGradientBoosting using the same train/test split and 13 input features.

Result: The outcome was highly imbalanced, with 1,159 of 29,353 pages labeled as went-dark, or approximately 3.95%; the models therefore showed an important trade-off between detecting rare events and maintaining precision.

Use: The resulting signals are best treated as decision support for human content and SEO review rather than as an automatic ranking or publishing system.

Headline finding: Accuracy alone can make a model appear strong on this imbalanced problem. The results show why recall, precision, F1, PR-AUC and the base rate should be considered together.

2. Introduction / Problem Statement

Search visibility is not static. A page can receive impressions and clicks during one period and later show substantially weaker search performance. For a content team, the practical problem is not simply predicting a number: it is deciding which pages deserve human attention first.

This study frames the problem as a classification task. The objective is to use information available during an earlier observation window to identify pages associated with a later loss of discoverability.

The intended decision is therefore a prioritization decision: which pages should an analyst investigate? The model is not intended to automatically edit, delete, redirect, publish, or otherwise change content.

Research question: Can February search-performance and content features provide useful signals for identifying pages that become “went dark” in the following March observation window?

Outcome definition

The target variable is went_dark. The final dataset contains 1,159 positive cases out of 29,353 modeling rows, producing a positive-class rate of approximately 3.95%.

Exclusions and missing data

The modeling universe was restricted to records that could be matched across the feature and outcome construction required for the study. Missing values were handled within the modeling workflow rather than silently dropping observations.

Several variables contained missing values, including word count, character count, search volume, competition, and backlinks. The modeling workflow therefore used imputation where required.

Public-safety note: This paper intentionally does not expose client names, private URLs, raw search queries, credentials, or other private information.

4. Methodology

Modeling setup

The analysis compares a simple majority-class baseline with two supervised machine-learning models:

  • Dummy Classifier
  • Logistic Regression
  • HistGradientBoosting

Validation design

The final modeling data was divided into a training set of 23,482 rows and a test set of 5,871 rows. The models were evaluated on the same held-out test split so that their results could be compared fairly.

Class imbalance

Only 3.95% of observations belonged to the positive went-dark class. This makes accuracy an incomplete metric because a model can achieve high accuracy largely by predicting the majority class.

Leakage considerations

The feature window precedes the label window. The outcome period is therefore kept separate from the input features used to make the prediction. This temporal ordering reduces the risk of using future outcome information as a predictor.

Evaluation metrics

Because the positive class is rare, the evaluation considers accuracy, precision, recall, F1, ROC-AUC and PR-AUC rather than accuracy alone.

Interpretation rule: A model score is a signal for investigation, not proof that a page will lose rankings or that a particular content change will cause improvement.

What the results mean

Logistic Regression identified a large share of the positive cases, with recall of 0.8793, but its precision was only 0.0905. This means the model can be useful as a broad screening signal, but many pages flagged by it would require human investigation.

HistGradientBoosting achieved the same overall accuracy as the dummy baseline and a higher PR-AUC of 0.2189, but its recall at the evaluated operating point was only 0.0043. It therefore did not provide a useful high-recall screening behavior at that threshold.

Main result: The experiments demonstrate that model evaluation must match the decision problem. For a rare “went dark” event, a 96% accuracy score does not mean that the model is effectively finding pages that need attention.

6. Limitations & Honest Framing

This study is a decision-support experiment, not a production ranking system. The results describe relationships observed in the available FlyRank data and validation design.

This work does not prove:

  • That any feature causes a page to lose discoverability.
  • That the model will improve search rankings.
  • That model scores represent causal risk.
  • That the model will generalize to every client or content type.
  • That the recommendations should be executed automatically.

Generalization

Search behavior, content types, competition and site conditions can change over time. Results may therefore not generalize to unseen clients, future search behavior, or content types not represented in the original dataset.

Human oversight

Every recommendation requires human review. Analysts should check content accuracy, search intent, business context, evidence and alternative explanations before taking action.

No-go principle: The system should not automatically publish content, delete pages, create redirects, change metadata, make guaranteed ranking claims, or replace editorial judgment.

7. Ranked Recommendations

The following action queue translates the analysis into a practical human-review workflow. The ranking is a prioritization framework, not an automated command list.

#1 · HIGH PRIORITY · DECAY

Refresh content showing performance decay

Evidence: Observed decline in performance over time.

Human action: Review the page's current accuracy, search intent, freshness and competitive context before deciding whether an update is justified.

#2 · HIGH PRIORITY · LOW_CTR

Review pages with high impressions but weak CTR

Evidence: Visibility is present but engagement is comparatively weak.

Human action: Inspect the query/page alignment and determine whether the title, snippet or content positioning needs review.

#3 · MEDIUM PRIORITY · PERFORMANCE_DROP

Investigate pages with measurable performance drops

Evidence: Recent performance is weaker than the available baseline.

Human action: Check whether the change may be related to seasonality, competition, technical factors, content changes or another cause.

#4 · MEDIUM PRIORITY · OPPORTUNITY

Review pages with improvement opportunity

Evidence: Model signals indicate pages worth further investigation.

Human action: Use the model as a screening signal and combine it with editorial and SEO judgment before taking action.
